# Client Integration

AIhub provides an OpenAI-compatible API and can be connected from any client that allows a custom API Base. This page uses Claude Code, Codex, and AnythingLLM as examples.

AIhub endpoint:

```text
https://aihub.skrepy.dpdns.org/
```

> Field naming differs across clients: Claude Code uses `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`; Codex and AnythingLLM use `OPENAI_BASE_URL` and `OPENAI_API_KEY`. The sections below explain each client separately.

---

## Before you start

Before configuring a client, make sure you have the following:

- An API key created in AIhub
- A model name that is currently available, for example `hy3`
- Network access to `https://aihub.skrepy.dpdns.org/`

Different clients use different names for the same values. The mapping is shown below:

| Meaning  | Common field names                          |
| -------- | ------------------------------------------- |
| API Key  | API Key / Key / Token                       |
| Base URL | Base URL / API Base / Endpoint / Server URL |
| Model    | Model / Model Name / 模型名                 |

## Claude Code

Claude Code can be configured through environment variables or `settings.json`. To connect it to AIhub, point requests to AIhub and use the corresponding key.

### Configuration file locations

Claude Code has two `settings.json` levels:

- **User level**: applies to all projects
  - Windows: `%USERPROFILE%\.claude\settings.json`
  - macOS / Linux: `~/.claude/settings.json`
- **Project level**: applies only to the current project
  - `<project root>\\.claude\\settings.json`

Example path on Windows:

```text
C:\Users\YourName\.claude\settings.json
```

If the file does not exist, create a new `settings.json` file.

### Open the config file

**Option 1: File manager**

1. Open File Explorer and go to `C:\Users\YourName\.claude\`
2. Find or create `settings.json`
3. Open it with VS Code or Notepad

**Option 2: Command line**

Windows (PowerShell):

```powershell
notepad $env:USERPROFILE\.claude\settings.json
```

macOS / Linux:

```bash
code ~/.claude/settings.json
```

### Full configuration example

Here is a complete `settings.json` example for AIhub:

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxxxx",
    "ANTHROPIC_BASE_URL": "https://aihub.skrepy.dpdns.org",
    "ANTHROPIC_MODEL": "hy3",
    "ANTHROPIC_SMALL_FAST_MODEL": "hy3",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "hy3",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "hy3",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "hy3",
    "CLAUDE_CODE_SUBAGENT_MODEL": "hy3",
    "CLAUDE_CODE_MAX_OUTPUT_TOKENS": "81929",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1"
  },
  "permissions": {
    "allow": ["Bash(curl -X GET \"http://localhost:3000/api/test\")"],
    "deny": []
  },
  "enabledPlugins": {
    "frontend-design@claude-plugins-official": true
  }
}
```

### Configuration notes

**Model-related variables in `env`**

| Variable                         | Purpose                           | Example                          |
| -------------------------------- | --------------------------------- | -------------------------------- |
| `ANTHROPIC_AUTH_TOKEN`           | AIhub API key for authentication  | `sk-xxxxxx`                      |
| `ANTHROPIC_BASE_URL`             | Request destination, set to AIhub | `https://aihub.skrepy.dpdns.org` |
| `ANTHROPIC_MODEL`                | Default model                     | `hy3`                            |
| `ANTHROPIC_SMALL_FAST_MODEL`     | Model used for lightweight tasks  | `hy3`                            |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | Sonnet tier model                 | `hy3`                            |
| `ANTHROPIC_DEFAULT_OPUS_MODEL`   | Opus tier model                   | `hy3`                            |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL`  | Haiku tier model                  | `hy3`                            |
| `CLAUDE_CODE_SUBAGENT_MODEL`     | Model used by subagents           | `hy3`                            |

> When connecting only to AIhub, you do not have to set every tier variable to the same value. However, pointing them to a single available model avoids errors when Claude Code requests a tier-specific model.

**Other runtime variables**

| Variable                                   | Purpose                               | Example |
| ------------------------------------------ | ------------------------------------- | ------- |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`            | Maximum output tokens per response    | `81929` |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | Disable non-essential network traffic | `1`     |

**Top-level settings**

| Setting             | Purpose                               |
| ------------------- | ------------------------------------- |
| `env`               | Environment variables for Claude Code |
| `permissions.allow` | Allowed command allowlist             |
| `permissions.deny`  | Denied command list                   |
| `enabledPlugins`    | Enabled plugin toggles                |

### Minimum working config

If you only need to verify connectivity, this is enough:

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxxxx",
    "ANTHROPIC_BASE_URL": "https://aihub.skrepy.dpdns.org",
    "ANTHROPIC_MODEL": "hy3"
  }
}
```

If no tier-specific model is set, Claude Code falls back to `ANTHROPIC_MODEL`.

### Configure through system environment variables

You can also set environment variables directly in the shell without editing the config file:

Windows (PowerShell):

```powershell
$env:ANTHROPIC_AUTH_TOKEN = "sk-xxxxxx"
$env:ANTHROPIC_BASE_URL = "https://aihub.skrepy.dpdns.org"
$env:ANTHROPIC_MODEL = "hy3"
```

macOS / Linux:

```bash
export ANTHROPIC_AUTH_TOKEN=sk-xxxxxx
export ANTHROPIC_BASE_URL=https://aihub.skrepy.dpdns.org
export ANTHROPIC_MODEL=hy3
```

> `ANTHROPIC_AUTH_TOKEN` and `ANTHROPIC_BASE_URL` in the environment take precedence over the values in `settings.json`.

### Steps

1. Open `settings.json`
2. Add `ANTHROPIC_AUTH_TOKEN` under `env`
3. Add `ANTHROPIC_BASE_URL` under `env`
4. Add `ANTHROPIC_MODEL` under `env`
5. Save the file and restart Claude Code
6. Send a message to verify the setup

### Common issues

**Connection failed**

Check these items in order:

- Is `settings.json` valid JSON?
- Does `ANTHROPIC_BASE_URL` contain extra spaces or a missing `https://` prefix?
- Is `ANTHROPIC_AUTH_TOKEN` copied in full?
- Did you restart Claude Code after editing?
- Can your network reach `https://aihub.skrepy.dpdns.org`?

**JSON format error**

This is usually caused by trailing commas, missing quotes, or mismatched braces. Start from the minimum config and add fields gradually.

**Cannot chat after saving the config**

This is usually caused by an unavailable model name, Claude Code not actually routing through AIhub, or AIhub not exposing the selected model. Use curl to verify the API first.

## Codex

First install the Codex enhancement tool: [Codex++](https://codexpp.cc)

After installation, launch the Codex++ management tool.

In the left sidebar, choose "Vendor Config" and add a new vendor.

Set the integration mode to "Pure API".

Set Base URL to `https://aihub.skrepy.dpdns.org/v1`.

Then fill in your API key and the AI model you want to use.

<Picture url="/img/clients/codex_provider_config.webp" info="Codex provider example configuration" />

Click Save in the upper-right corner, then select the vendor you just created.

Finally, click "Restart Codex++" in the upper-right corner to finish setup.

## AnythingLLM

AnythingLLM supports custom OpenAI-compatible providers through `Generic OpenAI`.

### Setup steps

1. Open AnythingLLM (Desktop or Docker)
2. Go to Settings → AI Provider → LLM
3. Search for `Generic OpenAI` in the LLM provider list and select it
4. Fill in the Base URL
5. Fill in the API Key
6. Fill in the Chat Model Name
7. Configure Token Context Window and Max Tokens if needed
8. Save the settings
9. Create a workspace and send a test message

### Fields

<Picture url="/img/clients/AnythingLLM_config.webp" info="AnythingLLM configuration" />

- **LLM Provider**: choose `Generic OpenAI`
- **Base URL**: `https://aihub.skrepy.dpdns.org/v1`
- **API Key**: your AIhub key
- **Chat Model Name**: a valid model name such as `hy3`
- **Token Context Window**: set according to model limits, such as `16000` or `128000`
- **Max Tokens**: adjust as needed, such as `1024` or `2048`

> AnythingLLM uses the `OPENAI_API_KEY` field; do not write `ANTHROPIC_*`.

### Troubleshooting

- Is the provider set to `Generic OpenAI`?
- Is the Base URL complete, including the `/v1` suffix?
- Is the model available?
- Did you save the configuration?

## General configuration rules

The key differences between clients usually come down to two things:

**Field naming system**:

- Anthropic-style fields for Claude Code: `ANTHROPIC_*`
- OpenAI-style fields for Codex and AnythingLLM: `OPENAI_*`

Check the actual field names used by your client before configuring it.

**Base URL format**:

- Most OpenAI-compatible clients require Base URL to end with `/v1`
- Some clients, such as Claude Code, accept the root address without the suffix
- If connection fails, try adding or removing `/v1` at the end of the Base URL

---

## Common troubleshooting order

When integration fails, check the following in order:

1. Is the key correct?
2. Is the Base URL `https://aihub.skrepy.dpdns.org/`? (Pay attention to the `/v1` suffix.)
3. Is the model name correct?
4. Does the client support the OpenAI-compatible API?
5. Has the configuration been saved?
6. Is there any network access restriction?
