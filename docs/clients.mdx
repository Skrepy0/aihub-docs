# Client Integration

AIhub provides an OpenAI-compatible interface, supporting integration with any client that allows a custom API Base. This page uses Claude Code, Codex, and AnythingLLM as examples to illustrate specific configuration methods.

AIhub endpoint:

```text
https://aihub.skrepy.dpdns.org/
```

> Field naming differences: Claude Code uses `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`; OpenAI-compatible clients like Codex and AnythingLLM use `OPENAI_BASE_URL` and `OPENAI_API_KEY`. The following sections describe the actual fields used by each client.

---

## Prerequisites

Before starting configuration, confirm the following three items:

- An API Key has been created in AIhub
- The currently available model name is known (e.g., `hy3`)
- The network can access `https://aihub.skrepy.dpdns.org/`

Different clients use different naming conventions for configuration items. The mapping is as follows:

| Actual meaning | Common field names                          |
| -------------- | ------------------------------------------- |
| API Key        | API Key / Key / Token                       |
| Base URL       | Base URL / API Base / Endpoint / Server URL |
| Model          | Model / Model Name                          |

## Claude Code

Claude Code specifies the model service address and key via environment variables or a `settings.json` file. To connect to AIhub, point the requests to AIhub and fill in the corresponding Key.

### Configuration File Location

Claude Code's `settings.json` has two levels:

- **User-level**: applies to all projects
  - Windows: `%USERPROFILE%\.claude\settings.json`
  - macOS / Linux: `~/.claude/settings.json`
- **Project-level**: applies only to the current project
  - `<project root>\.claude\settings.json`

Example actual path (Windows):

```text
C:\Users\YourUsername\.claude\settings.json
```

If the file does not exist, create a new `settings.json`.

### Opening the Configuration File

**Method 1: File Explorer**

1. Open File Explorer and navigate to `C:\Users\YourUsername\.claude\`
2. Find or create `settings.json`
3. Open it with VS Code or Notepad

**Method 2: Command Line**

Windows (PowerShell):

```powershell
notepad $env:USERPROFILE\.claude\settings.json
```

macOS / Linux:

```bash
code ~/.claude/settings.json
```

### Complete Configuration Example

Below is a full `settings.json` for connecting to AIhub:

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxxxx",
    "ANTHROPIC_BASE_URL": "https://aihub.skrepy.dpdns.org",
    "ANTHROPIC_MODEL": "hy3",
    "ANTHROPIC_SMALL_FAST_MODEL": "hy3",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "hy3",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "hy3",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "hy3",
    "CLAUDE_CODE_SUBAGENT_MODEL": "hy3",
    "CLAUDE_CODE_MAX_OUTPUT_TOKENS": "81929",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1"
  },
  "permissions": {
    "allow": ["Bash(curl -X GET \"http://localhost:3000/api/test\")"],
    "deny": []
  },
  "enabledPlugins": {
    "frontend-design@claude-plugins-official": true
  }
}
```

### Configuration Fields Explained

**Model‑related variables in `env`**

| Variable                         | Purpose                               | Example                          |
| -------------------------------- | ------------------------------------- | -------------------------------- |
| `ANTHROPIC_AUTH_TOKEN`           | AIhub API Key for authentication      | `sk-xxxxxx`                      |
| `ANTHROPIC_BASE_URL`             | Request endpoint, set to AIhub        | `https://aihub.skrepy.dpdns.org` |
| `ANTHROPIC_MODEL`                | Default model                         | `hy3`                            |
| `ANTHROPIC_SMALL_FAST_MODEL`     | Model used for lightweight/fast tasks | `hy3`                            |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | Sonnet‑tier model                     | `hy3`                            |
| `ANTHROPIC_DEFAULT_OPUS_MODEL`   | Opus‑tier model                       | `hy3`                            |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL`  | Haiku‑tier model                      | `hy3`                            |
| `CLAUDE_CODE_SUBAGENT_MODEL`     | Model used by sub‑agents              | `hy3`                            |

> If you are only connecting to AIhub, you are not required to set all tier variables to the same value; however, pointing them all to an available model prevents Claude Code from failing when it attempts to call a specific tier that is not available.

**Other runtime parameters**

| Variable                                   | Purpose                                          | Example |
| ------------------------------------------ | ------------------------------------------------ | ------- |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`            | Maximum output tokens per response               | `81929` |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | Disable non‑essential network requests, `1` = on | `1`     |

**Top‑level configuration items**

| Config item         | Purpose                                            |
| ------------------- | -------------------------------------------------- |
| `env`               | Environment variables injected into Claude Code    |
| `permissions.allow` | Whitelist of commands allowed to run automatically |
| `permissions.deny`  | List of commands to block                          |
| `enabledPlugins`    | Toggle for enabled plugins                         |

### Minimal Working Configuration

If you only need to verify connectivity, the following configuration is sufficient:

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxxxx",
    "ANTHROPIC_BASE_URL": "https://aihub.skrepy.dpdns.org",
    "ANTHROPIC_MODEL": "hy3"
  }
}
```

If tier‑specific models are not explicitly set, Claude Code falls back to `ANTHROPIC_MODEL`.

### Configuring via System Environment Variables

You can also set environment variables directly in the terminal without modifying the configuration file:

Windows (PowerShell):

```powershell
$env:ANTHROPIC_AUTH_TOKEN = "sk-xxxxxx"
$env:ANTHROPIC_BASE_URL = "https://aihub.skrepy.dpdns.org"
$env:ANTHROPIC_MODEL = "hy3"
```

macOS / Linux:

```bash
export ANTHROPIC_AUTH_TOKEN=sk-xxxxxx
export ANTHROPIC_BASE_URL=https://aihub.skrepy.dpdns.org
export ANTHROPIC_MODEL=hy3
```

> Environment variables `ANTHROPIC_AUTH_TOKEN` and `ANTHROPIC_BASE_URL` take precedence over the settings in `settings.json`.

### Configuration Steps

1. Open `settings.json`
2. In `env`, fill in `ANTHROPIC_AUTH_TOKEN`
3. In `env`, fill in `ANTHROPIC_BASE_URL`
4. In `env`, fill in `ANTHROPIC_MODEL`
5. Save the file and restart Claude Code
6. Send a test message to verify

### Common Issues

**Connection failure**

Check in order:

- Is `settings.json` valid JSON?
- Does `ANTHROPIC_BASE_URL` contain extra spaces or omit `https://`?
- Is `ANTHROPIC_AUTH_TOKEN` copied completely?
- Did you restart Claude Code after making changes?
- Can the network reach `https://aihub.skrepy.dpdns.org`?

**JSON format error**

Usually caused by trailing commas, missing quotes, or mismatched braces. Revert to the minimal configuration and gradually add back settings.

**Cannot chat after saving configuration**

Often caused by an unavailable model name, AIhub not supporting the specified model, or requests not actually going through AIhub. Use curl to verify the endpoint itself is working.

## Codex

First, download an enhancement tool for CodexApp: [Codex++](https://codexpp.cc)

After downloading and installing, launch the Codex++ management tool.

In the left sidebar, select "Provider Configuration", then add a provider.

Choose "Pure API" as the integration mode.

Fill in the Base URL as `https://aihub.skrepy.dpdns.org/v1`

Then enter your `API Key` and the AI model you intend to use.

<Picture url="/img/clients/codex_provider_config.webp" info="Codex provider example configuration" />

Click "Save" in the upper right corner, then select the provider you just created.

Finally, click "Restart Codex++" in the upper right corner to complete the configuration.

## AnythingLLM

AnythingLLM supports connecting to custom OpenAI‑compatible services via the `Generic OpenAI` provider.

### Configuration Steps

1. Open the AnythingLLM application (Desktop or Docker)
2. Go to Settings → AI Providers → Large Language Model (LLM)
3. Type `Generic OpenAI` in the LLM provider search box and select it
4. Fill in the Base URL
5. Fill in the API Key
6. Fill in the Chat Model Name
7. Adjust Token Context Window and Max Tokens as needed
8. Save the configuration
9. Create a new workspace and send a test message to verify

### Fields to Fill

<Picture url="/img/clients/AnythingLLM_config.webp" info="AnythingLLM configuration" />

- **LLM Provider**: Select `Generic OpenAI`
- **Base URL**: `https://aihub.skrepy.dpdns.org/v1`
- **API Key**: Your AIhub Key
- **Chat Model Name**: Available model name (e.g., `hy3`)
- **Token Context Window**: Set according to model limits (e.g., `16000`, `128000`)
- **Max Tokens**: Configure as needed (e.g., `1024`, `2048`)

> AnythingLLM uses the `OPENAI_API_KEY` field; do not use `ANTHROPIC_*`.

### Troubleshooting

- Is the provider set to `Generic OpenAI`?
- Is the Base URL complete (with `/v1` suffix)?
- Is the model name available?
- Was the configuration saved?

## General Configuration Principles

The key differences across clients are mainly in two areas:

**Field naming conventions**:

- Anthropic style (Claude Code): uses `ANTHROPIC_*` prefix
- OpenAI style (Codex, AnythingLLM and upper‑layer tools): uses `OPENAI_*` prefix

Before configuring, confirm the actual field names used by the client to avoid mixing them.

**Base URL format**:

- Most OpenAI‑compatible clients require the Base URL to end with `/v1`
- Some clients (e.g., Claude Code) accept the root address without the suffix
- If connection fails, try adding or removing `/v1` at the end of the Base URL

---

## General Troubleshooting Sequence

If integration fails, check in this order:

1. Is the Key correct?
2. Is the Base URL `https://aihub.skrepy.dpdns.org/` (pay attention to the `/v1` suffix)?
3. Is the model name correct?
4. Does the client support the OpenAI‑compatible interface?
5. Has the configuration been saved?
6. Are there any network access restrictions?
