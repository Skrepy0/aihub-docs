# AIhub 使用指南

AIhub is an AI service routing platform based on [new-api](https://docs.newapi.pro). With AIhub, you can call multiple AI models through a unified API key and OpenAI-compatible interface.

If you are using the docs for the first time, we recommend reading in the following order:

1. Learn the core features and positioning of AIhub
2. Create and obtain an API key
3. Configure the key and Base URL in your client or code
4. Test with a sample request
5. Check the FAQ when you run into problems

---

## Overview

AIhub provides the following core capabilities:

- A unified entry point for AI APIs that aggregates multiple model services
- One API key that can be reused across tools, apps, and scripts
- Full compatibility with the OpenAI API style to reduce integration cost

If you have used an OpenAI-compatible API before, you only need to replace three configuration values:

- `API Key`
- `Base URL`
- `model`

---

## Quick Start

### Log in to AIhub

Visit [AIhub](https://aihub.skrepy.dpdns.org/) and complete registration and sign-in.

### Create an API Key

Go to the [API Key management page](https://aihub.skrepy.dpdns.org/keys) and create a new key. Fill in the following fields:

- Name: any label that helps you identify the application
- Group: the model group this key can access
- Expiration (optional): set a validity period, or leave it blank for no expiry

> Each API key can only call models in its assigned group. Please confirm the group selection before creating the key.

### Record the Base URL

Use the following AIhub server address as your Base URL:

```text
https://aihub.skrepy.dpdns.org
```

### Choose a model

When your client or code asks for a model name, make sure the model is allowed for the current key group.

You can browse available models in the [model marketplace](https://aihub.skrepy.dpdns.org/pricing).

## API Key Configuration

An API key is the credential used to authenticate requests to AIhub. Every request must include the following three values:

- `API Key`: the authentication credential
- `Base URL`: the server address
- `model`: the target model name

### In third-party clients

Clients that support the OpenAI-compatible protocol usually expose these fields:

- **API Key**: paste the AIhub key here
- **Base URL**: use `https://aihub.skrepy.dpdns.org`
- **Model**: choose a valid model name

### In code

We recommend using environment variables instead of hard-coding the key:

```bash
AIHUB_API_KEY=sk-xxxxxx
AIHUB_BASE_URL=https://aihub.skrepy.dpdns.org
```

Your program can then read the values from the environment.

## Request Examples

The following examples use the OpenAI-compatible API format. Replace `Base URL`, `API Key`, and `model` with your real values.

### curl

```bash
curl https://aihub.skrepy.dpdns.org/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      {
        "role": "user",
        "content": "Hello, what model are you?"
      }
    ]
  }'
```

### JavaScript (Node.js)

```javascript
const response = await fetch('https://aihub.skrepy.dpdns.org/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${process.env.AIHUB_API_KEY}`,
  },
  body: JSON.stringify({
    model: 'gpt-4o-mini',
    messages: [{ role: 'user', content: 'Hello, what model are you?' }],
  }),
});

const data = await response.json();
console.log(data);
```

### Python

```python
import os
import requests

url = "https://aihub.skrepy.dpdns.org/v1/chat/completions"
headers = {
    "Authorization": f"Bearer ${os.getenv('AIHUB_API_KEY')}",
    "Content-Type": "application/json",
}
body = {
    "model": "gpt-4o-mini",
    "messages": [
        {"role": "user", "content": "Hello, what model are you?"}
    ],
}

response = requests.post(url, headers=headers, json=body)
print(response.json())
```

## Client Configuration Notes

When using an OpenAI-compatible client, you typically only need to fill in three fields:

- `API Key`: AIhub key
- `Base URL`: `https://aihub.skrepy.dpdns.org`
- `Model`: a valid model name

### Common field name mapping

Different clients may use different labels. Common variants include:

| Meaning  | Common field names                          |
| -------- | ------------------------------------------- |
| API Key  | API Key / Key / Token / API Token           |
| Base URL | Base URL / API Base / Endpoint / Server URL |
| Model    | Model / Model Name                          |

### Verify the configuration

After setting everything up, send a simple test message such as:

> Hello

If the response comes back normally, the configuration is working.

## FAQ

### 401 Unauthorized

**Possible reasons**:

- The API key is incorrect or expired
- The request header is missing `Authorization: Bearer <key>`

**Fix**: copy the key again and confirm the header format.

### 403 Forbidden

**Possible reasons**:

- The current key cannot access the requested model
- The account does not have sufficient permissions

**Fix**: check whether the model is inside the key group, or switch to an available model.

### 429 Too Many Requests

**Possible reasons**: you are sending requests too frequently.

**Fix**: reduce request frequency, increase retry intervals, and check for accidental loops.

### Model not found or unavailable

**Possible reasons**:

- The `model` name is misspelled
- The model has been taken offline
- The current key does not have access to the model

**Fix**: confirm the available model list in the marketplace and use the correct name.

### Client connection failed

**Possible reasons**:

- The Base URL is incorrect
- The network cannot reach AIhub
- The client does not support the OpenAI-compatible protocol

**Fix**: confirm the Base URL is `https://aihub.skrepy.dpdns.org`, test connectivity with curl, and check the client docs.

## Security Tips

API keys are sensitive credentials. Follow these rules:

- Do not commit them to public or private Git repositories
- Do not share them through screenshots or recordings
- Do not hard-code them in frontend code or easily reversible client files
- Reset the key immediately if you suspect a leak
