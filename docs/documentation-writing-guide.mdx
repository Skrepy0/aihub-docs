# Documentation Writing Guide

This page explains the style used in the AIhub docs and the preferred way to add or edit pages.

---

## Writing principles

- Keep explanations short and actionable
- Start from the user task, then explain the details
- Prefer examples over abstract descriptions
- Keep field names, URLs, and model names accurate

---

## Page structure

A typical page should include:

1. A clear title
2. A short overview of the topic
3. Step-by-step instructions or examples
4. Common errors and fixes
5. Links to related pages

---

## Language style

- Use plain language
- Use consistent terminology across all pages
- Keep the Chinese and English versions aligned in meaning
- Avoid mixing untranslated labels into the wrong locale version

---

## Code and configuration examples

When adding code blocks:

- Keep them minimal and runnable where possible
- Use real field names and realistic values
- Update examples when the integration flow changes

---

## Linking rules

- Link to related docs pages using relative paths
- Keep links working in both languages
- Prefer canonical page names when possible

---

## Suggested workflow for new content

1. Draft the Chinese version if needed
2. Add the English version with matching structure
3. Review titles, headings, and links
4. Build the site and test both locales
