# 📘 AIhub Docs 文档编写指南

欢迎参与 AIhub Docs 文档的编写！本文档将帮助你快速了解 MDX 语法、Docusaurus 框架、项目结构以及自定义组件的使用方法。请仔细阅读以下内容，以便高效地创作出格式规范、视觉统一的文档页面。

---

## 📝 1. MDX 常用格式与写法

MDX 是 Markdown 与 JSX 的结合体，允许你在 Markdown 中直接使用 React 组件。所有 `.md` 和 `.mdx` 文件都会被当作 MDX 解析（推荐使用 `.mdx` 扩展名）。

### 1.1 基础YAML语法

在 Docusaurus 中，每个 MDX 文档的**顶部**可以通过 `---` 包裹一个 **YAML 格式**的配置块，称为 **Front Matter**。它用于定义页面的标题、侧边栏位置、描述等元数据。

#### 🧱 基本数据类型

##### 1. 字符串（String）

- 可以不加引号，但**包含特殊字符**（如 `:`、`#`、`[` 等）时建议使用单引号 `'` 或双引号 `"`。
- **示例**：
  ```yaml
  title: 快速开始
  description: '包含冒号: 这是一个描述'
  sidebar_label: '入门指南'
  ```

##### 2. 数字（Number）

- 支持整数和浮点数，直接书写。
- **示例**：
  ```yaml
  sidebar_position: 1
  version: 2.5
  ```

##### 3. 布尔值（Boolean）

- 可写为 `true` / `false`，或 `yes` / `no`，`on` / `off`（推荐使用 `true` / `false`）。
- **示例**：
  ```yaml
  draft: false
  hide_title: true
  ```

##### 4. 列表 / 数组（List）

- 使用短横线 `- ` 加空格表示列表项。
- **示例**：
  ```yaml
  keywords:
    - docusaurus
    - mdx
    - yaml
  ```
- 也支持行内紧凑格式（类似 JSON）：
  ```yaml
  keywords: [docusaurus, mdx, yaml]
  ```

##### 5. 键值对（对象 / 映射）

- 使用 `key: value` 格式，**冒号后必须有一个空格**。
- 嵌套结构通过缩进实现。
- **示例**：
  ```yaml
  author:
    name: Skrepy
    email: skrepy@example.com
  ```

---

#### ⚠️ 缩进规则（极其重要）

- **只能使用空格缩进**，**严禁使用 Tab**。
- 同一层级缩进的空格数必须一致（通常为 2 或 4 个空格）。
- 不一致的缩进会导致解析失败。

---

#### 📝 注释

- 使用 `#` 开头，从 `#` 到行尾的内容会被忽略。
- **示例**：
  ```yaml
  # 这是注释
  title: 我的文档 # 行尾注释也可以
  ```

---

#### ✅ 正确示例

```yaml
---
# 文档标题
title: 'YAML 语法指南'
sidebar_position: 2
description: 学会在 MDX Front Matter 中正确使用 YAML
keywords:
  - yaml
  - mdx
  - frontmatter
draft: false
hide_title: false
image: /img/share.png
---
```

---

#### ❌ 常见错误

| 错误写法                       | 正确写法                      | 原因                |
| ------------------------------ | ----------------------------- | ------------------- |
| `title:Hello`                  | `title: Hello`                | 冒号后必须有空格    |
| 使用 Tab 缩进                  | 使用空格缩进                  | YAML 禁止 Tab       |
| `keywords: [docusaurus, mdx`   | `keywords: [docusaurus, mdx]` | 括号必须闭合        |
| 缩进不一致（2空格和4空格混用） | 统一缩进空格数                | YAML 严格要求一致性 |

---

### 1.2 基础 Markdown 语法

| 功能         | 写法示例                                                        |
| ------------ | --------------------------------------------------------------- |
| **标题**     | `# 一级标题` `## 二级标题` ... `###### 六级标题`                |
| **段落**     | 直接书写文本，空行分隔段落                                      |
| **粗体**     | `**粗体文字**`                                                  |
| **斜体**     | `*斜体文字*`                                                    |
| **删除线**   | `~~删除线~~`                                                    |
| **无序列表** | `- 项目1` 或 `* 项目2`                                          |
| **有序列表** | `1. 第一项` `2. 第二项`                                         |
| **链接**     | `[显示文本](https://example.com)`                               |
| **图片**     | `![替代文本](../img/logo.png)`（推荐使用自定义 `Picture` 组件） |
| **代码块**   | ` ```语言` ... ` ``` `                                          |
| **行内代码** | `` `code` ``                                                    |
| **引用**     | `> 引用内容`                                                    |
| **表格**     | `\| 列1 \| 列2 \|` 等                                           |
| **分割线**   | `---` 或 `***`                                                  |

### 1.3 在 MDX 中嵌入 React 组件

你可以直接在 MDX 文件中导入并使用 React 组件，就像在 JSX 中一样：

```
import MyComponent from '@site/src/components/MyComponent';

<MyComponent prop="value" />
```

组件可以接受 props，并支持嵌套子元素。

> **注意**：MDX 中的 `{}` 内可执行 JavaScript 表达式，例如 `{2 + 2}`。

## 🧩 2. 文档结构

一份 MDX 文档主要由三部分构成：顶部的 **Front Matter（前言/元数据）**、紧随其后的 **React 组件导入区**，以及核心的 **Markdown 内容**。

下面拆解一个 Docusaurus 中的 MDX 文档示例来详细说明：

```mdx
---
title: '欢迎使用 AIhub Docs' # ① Front Matter (元数据)
sidebar_label: '首页'
description: 'AIhub Docs 的官方文档，包含使用指南与API参考。'
---

# ② 导入外部组件 (可选)

import LinkBox from '@site/src/components/LinkBox';
import Picture from '@site/src/components/Picture';

# ③ 正文内容

## 快速开始

这里是文档的正文部分，你可以使用标准的 Markdown 语法。

<Picture url="/img/logo.png" height="200" />

你也可以在这里使用上面导入的 React 组件：

<LinkBox url="https://aihub.skrepy.dpdns.org/" title="AIhub" />
```

---

### 2.1 Front Matter（前言/元数据）

Front Matter 是 MDX 文档顶部的 YAML 格式配置块，用于定义页面的标题、描述、侧边栏标签等元数据。它由三个连续的短横线 `---` 包裹。

#### 常用字段

- **`title`** (可选): 页面的主标题，会显示在浏览器标签和搜索引擎结果中，不填则默认为mdx文件的无后缀文件名。
- **`sidebar_label`** (可选): 自定义在侧边栏中显示的标签，若不设置则默认使用 `title`。
- **`description`** (可选): 页面的简要描述，用于 SEO 优化。
- **`keywords`** (可选): 页面的关键词，辅助搜索引擎优化。
- **`image`** (可选): 页面分享时的预览图 URL。
- **`id`** (可选): 文档的唯一标识符，通常用于文档版本控制。
- **`hide_title`** (可选): 布尔值，设为 `true` 可隐藏页面顶部的标题。
- **`sidebar_position`** (可选): 整数，数字越小，文档在侧边栏中的排序越靠前

### 2.2 导入外部组件 (可选)

在 Front Matter 之后，正文内容之前，你可以像在 React 文件中一样，使用 `import` 语句引入需要的自定义组件或第三方库。

```mdx
import Picture from '@site/src/components/Picture';
import LinkBox from '@site/src/components/LinkBox';
```

### 2.3 正文内容

正文部分是文档的主体，由标准的 Markdown 语法和嵌入的 JSX/React 组件构成。

#### 标题 (Headings)

使用 `#` 符号来创建标题。

- **一级标题 (`#`)**: 通常是页面的主标题。**建议与 Front Matter 中的 `title` 保持一致**，以获得更好的 SEO 效果。
- **二级标题 (`##`)**: 用于划分主要章节。
- **三级标题 (`###`)**: 用于划分章节下的子主题。
- **四级标题 (`####`) 及以下**: 用于更细致的层级划分。

> **注意**：默认情况下，页面右侧的目录（TOC）会自动提取 `##` 和 `###` 级别的标题。

#### 正文与段落

- **段落**：直接书写文本，通过**空行**来分隔不同的段落。
- **换行**：在行末添加两个空格或使用 `\` 符号可以强制换行。

#### 列表

- **无序列表**：使用 `-`、`*` 或 `+` 符号。
- **有序列表**：使用数字加 `.` 符号。

#### 链接与图片

- **链接**：`[链接文本](URL)`。
- **图片**：`![替代文本](图片URL)`。

#### 代码块

使用三个反引号 **` ``` ** 并指定语言来创建语法高亮的代码块。

````markdown
```javascript
console.log('Hello, AIhub!');
```
````

#### 嵌入 React 组件

这是 MDX 最强大的特性。你可以在 Markdown 中像使用 HTML 标签一样使用之前导入的组件。

```
<Picture url="/img/logo.png" height="100" />
<LinkBox url="https://aihub.skrepy.dpdns.org/" title="AIhub" />
```

效果如下:

<Picture url="/img/logo.png" height="100" />
<LinkBox url="https://aihub.skrepy.dpdns.org/" title="AIhub" />

## 🗂️ 3. 项目结构

项目根目录结构如下（仅展示核心部分）：

```
aihub-docs/
├── docs/                  # 文档源文件（.mdx / .md）
├── src/
│   ├── components/        # 自定义 React 组件（全局复用）
│   │   ├── Picture.tsx
│   │   ├── LinkBox.tsx
│   │   └── ...
│   ├── ...
├── static/                # 静态资源（图片、favicon 等）
│   ├── img/
│   │   └── logo.png
│   └── ...
├── ...
```

### 主要目录说明

- **`docs/`**：存放所有文档源文件。支持子目录，最终网站的 URL 路径与目录结构对应。
- **`src/components/`**：存放自定义 React 组件，可在任何 MDX 文件中复用（见下文）。
- **`static/`**：存放静态文件（图片、字体、PDF 等），这些文件会被原样复制到构建输出目录，可通过**绝对路径**（以 `/` 开头）访问，例如 `/img/logo.png`。

## 🔧 4. 自定义组件使用指南

为了提升文档的丰富性和交互性，项目在 `src/components/` 下内置了一些实用组件。你可以在任何 `.mdx` 文件中通过 `@site` 别名导入它们。

### 4.1 导入组件

`@site` 是 Docusaurus 提供的别名，指向项目根目录。例如：

```
import Picture from '@site/src/components/Picture';
import LinkBox from '@site/src/components/LinkBox';
```

> 通常写在mdx文件的顶部

**注意**:在所有import结束后,需要有一空行
例如:

```
import Picture from '@site/src/components/Picture';
import LinkBox from '@site/src/components/LinkBox';

<Picture url="/img/logo.png" height="350" />
```

### 4.2 使用 `Picture` 组件（优化图片展示）

`Picture` 是一个用于在 MDX 文档中优雅插入图片的 React 组件，支持自定义高度、对齐方式和图注说明。

---

#### 导入

在 MDX 文件顶部导入组件：

```
import Picture from '@site/src/components/Picture';
```

---

#### 参数

| 属性     | 类型                            | 必填 | 说明                                                                                          |
| -------- | ------------------------------- | ---- | --------------------------------------------------------------------------------------------- |
| `url`    | `string`                        | ✅   | 图片路径，支持绝对路径（`/` 开头）或相对路径。                                                |
| `height` | `number`                        | ❌   | 图片高度（单位 px）。若指定，宽度自动适配，最大宽度 100%；若不指定，宽度为 100%，高度自适应。 |
| `info`   | `string`                        | ❌   | 图片下方的说明文字（图注）。                                                                  |
| `pos`    | `'left' \| 'center' \| 'right'` | ❌   | 图片对齐方式，默认 `'center'`。                                                               |

---

#### 使用示例

##### 基础用法（居中，固定高度）

```
<Picture url="/img/logo.png" height="50" />
```

效果：居中显示，高度 50px，宽度自适应。

## <Picture url="/img/logo.png" height="50" />

##### 带图注的左对齐图片

```
<Picture url="/img/logo.png" height="50" info="图注" pos="left" />
```

效果:

## <Picture url="/img/logo.png" height="50" info="图注" pos="left" />

##### 宽度自适应（无固定高度）

```
<Picture url="/img/logo.png" />
```

图片占满容器宽度，高度按比例缩放。

<Picture url="/img/logo.png" />

---

##### 居右带图注

```
<Picture url="/img/logo.png" pos="right" info="LOGO" />
```

## <Picture url="/img/logo.png" pos="right" info="LOGO" />

#### 📁 图片路径最佳实践

- **绝对路径（强烈推荐）**：以 `/` 开头，对应项目根目录下的 `static/` 文件夹。  
  例如：`/img/hero.png` → `static/img/hero.png`  
  ✅ 优点：在任何层级的 MDX 文件中都能正确引用，无需关心相对位置。

- **相对路径（谨慎使用）**：相对于当前 MDX 文件所在目录。  
  例如：`../img/logo.png` → 当前文件在 `docs/guide/` 下时，指向 `docs/img/logo.png`。  
  ❌ 缺点：文件移动或嵌套目录改变时容易失效，不推荐。

> 💡 建议：将所有图片统一存放在 `static/img/` 目录下，并使用绝对路径引用。

---

#### ⚠️ 注意事项

1. 若同时指定 `height` 和 `info`，图注会紧贴在图片下方。
2. `pos` 仅控制图片容器内对齐，不影响图注（图注始终居中）。
3. `info` 为空时不显示图注容器。

---

### 4.3 使用 `LinkBox` 组件（外链卡片）

`LinkBox` 用于生成美观的外部链接卡片，包含标题、副标题、图标和提示信息。

**示例：**

```
<LinkBox url="https://aihub.skrepy.dpdns.org/" title="AIhub" />
```

**完整参数：**

| 参数       | 类型   | 必填 | 说明                                                      |
| ---------- | ------ | ---- | --------------------------------------------------------- |
| `url`      | string | ✅   | 跳转链接                                                  |
| `title`    | string | ✅   | 卡片标题                                                  |
| `subtitle` | string | ❌   | 副标题（可选）                                            |
| `icon`     | string | ❌   | 自定义图标 URL（若不提供，自动从 `url` 获取 favicon）     |
| `tip`      | string | ❌   | 自定义提示文字（默认“前往以下网站，但是不保证安全性哦~”） |

---

## 📁 5. 静态资源存放与引用最佳实践

- **存放位置**：所有静态资源（图片、字体、文件等）统一放在 **`static/`** 目录下。
- **引用方式**：
  - **绝对路径（推荐）**：以 `/` 开头，指向 `static/` 根目录。例如，图片 `static/img/logo.png` 在 MDX 中写为 `/img/logo.png`。
  - **相对路径**：相对于当前 MDX 文件的位置。例如，若文件在 `docs/` 下，引用 `static/img/logo.png` 可写为 `../static/img/logo.png`（但层级较深时容易出错，不推荐）。

**示例（绝对路径）：**

```mdx
<Picture url="/img/logo.png" height="350" />
```

这样无论 MDX 文件在哪个目录，路径始终有效。

在提交文档前，请确认：

- [ ] 如果图片使用自定义组件，请检查其能否正常显示。
